# rb-03 · Runbook: checkout errors and authentication failures

**Rule:** When checkout-api is degraded with authentication errors, check authd on the core servers before touching the application servers.

## Symptoms
checkout-api reports degraded on application servers; users see failed logins or intermittent 401 responses; nginx on the same hosts is healthy.

## Diagnosis
checkout-api depends on authd, which runs on core-tier servers. Query services for `authd` in a failed or degraded state. A failed authd on a core server is the usual root cause, and restarting checkout-api will not help.

## Fix
Restart authd on the affected core server (rb-01). Core tier needs an admin's approval (ops-07). After the restart, confirm authd is active and that checkout-api recovers.
